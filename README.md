# 拾级 · 数学学习档案

面向家庭的数学学习档案：原卷浏览、成绩核对、复习记录、知识点线索。静态网页部署到 GitHub Pages，所有真实试卷与结构化学习记录先在本地加密再提交。

## 数据与权限

- `docs/` 是唯一发布目录。页面代码可公开，`data.enc` 与 `files/*.enc` 是加密资料。
- AES-256-GCM，随机12字节IV；PBKDF2-SHA256 / 600,000 次从口令派生密钥，每次资料构建生成新盐。
- 口令不上传、不硬编码、不存 localStorage。资料解密后只在页面内存中使用。浏览器下载 PDF 会生成本地明文，请按家庭资料管理。
- 这是客户端加密，不是服务器登录。公开密文可被离线尝试口令，须使用足够长的独立口令。口令丢失无法恢复。
- 更换口令不能撤回已被下载或留在 Git 历史中的旧密文，因此长期使用前应换强口令。
- 原件与临时目录 `.private/` 不提交；GitHub 保存可完整恢复的加密 PDF 与加密 JSON。

## 初次发布

1. 将本项目代码与 `docs` 中的加密文件推送到新仓库 `max-math-journal`。
2. 仓库 Settings → Pages → Build and deployment → Source 选择 GitHub Actions。
3. 运行 Deploy learning portal 工作流，完成后查看工作流返回的地址。
4. GitHub Free 通常需公开仓库来使用 Pages；公开内容必须仅包含本项目代码与加密文件。

## 新资料导入

需要 Python（含 `pypdf`）与 Node.js（仅使用内置模块）。在项目目录运行：

```powershell
python scripts/update.py 'C:\StudyMaterials\Math'
```

脚本会隐藏口令输入。可用 `--node` 指定 Node.js 完整路径。根据内容 SHA256 去重，保留现有核对记录与复习记录；新文件只登记档案，不猜测分数、日期和错误原因。扫描版面的重复判断仍需人工复核。文件内容变化会产生新档案，不自动当成旧档案覆盖。

每次运行前先拉取 GitHub 最新文件，避免覆盖在网页中更新的学习记录。完成后提交全部 `docs/data.enc` 和 `docs/files/*.enc`。同一批必须一起发布，不能混用不同加密批次。

## 网页修改如何同步

网页支持更新成绩、日期、核对状态，以及增删改复习记录。修改只在当前页面内存；点击“下载加密更新”得到 `data.enc`。将它替换仓库的 `docs/data.enc` 并提交，GitHub Actions 自动发布。下载不等于已同步，多设备同时编辑需避免覆盖。页面锁定会提醒尚未导出的修改。

## 更换口令

```powershell
python scripts/update.py --rekey
```

输入旧口令、新口令和确认口令（新口令至少16位）。将生成的整个加密资料批次一起提交发布。

## 完整性校验

运行 `node scripts/verify.mjs` 并通过标准输入提供口令，可验证全部PDF指纹、复习关联、错误口令拒绝与密文篡改检测。不要将口令写入脚本或提交仓库。

## 本地预览

```powershell
python -m http.server 8765 --directory docs
```

访问 `http://localhost:8765`。使用 HTTPS 或 localhost 才能调用浏览器加密功能。

## 分析边界

初版四份周练分数取自扫描批注，均标记待家庭核对；月考总分、考试日期尚未确认。知识点只是内容分类，不以试卷分数推断掌握度。初始8条待复习线索来自原卷可见扣分或叉号，均未确认错误原因。逐题错因与复测证据须结合原卷录入。没有班级数据、考试日期或可比难度时不生成排名或能力趋势。

原始13页扫描的分界为1–2、3–5、6–7、8–9、10–13页；第4、5页为重复扫描，第二份保留原第5页。月考保留试卷与答题纸；temp目录中的13页原始合并扫描作为独立原始档案加密保存，不重复计入成绩。后续目录新增导入不进行自动拆卷、旋转或 OCR，需要先整理或由人工核对。
